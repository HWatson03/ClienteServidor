# Refactor del backend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Refactorizar el backend Java para usar IDs `Long` coherentes con SQL, Lombok, DTOs independientes y APIs con sufijo `Api`, recreando el esquema Flyway para una base vacía.

**Architecture:** Mantener los módulos y capas actuales. Actualizar en conjunto entidades, relaciones JPA, repositorios, servicios y contratos HTTP; alinear Flyway con esas entidades y preservar reglas de negocio existentes.

**Tech Stack:** Java 21, Spring Boot 4, Spring Data JPA, PostgreSQL, Flyway, Lombok, Maven Wrapper.

**Spec:** `docs/superpowers/specs/2026-10-27-refactor-backend-ids-lombok-design.md`

## Global Constraints

- IDs de entidad Java: `Long`, campos `id<Entidad>`; PK SQL: `id_<entidad>`.
- Claves foráneas SQL usan el nombre de la PK del destino, como `archivos.id_carpeta`.
- Lombok reemplaza getters/setters y constructores manuales en entidades/servicios; evitar `@Data` en entidades JPA.
- UUID permanece solo para datos aleatorios no identificadores.
- Mantener rutas HTTP y reglas de negocio salvo conversiones de tipos exigidas.
- Preservar las modificaciones locales existentes.
